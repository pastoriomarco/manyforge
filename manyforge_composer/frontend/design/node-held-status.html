"Held until Run": a node that is executing but waiting for motion

After Execute, a motion node's operation is submitted but held until the operator presses Run. Today it shows as idle, so nothing says it is the one waiting. Each row is one way to show that state, next to the existing idle, running and success looks, and as a row inside a collapsed node.

Notes

  • Data: the runner already knows it. A motion node whose operation is held before admission is presented as INVALID, which the status contract turns into idle. Showing it needs a fifth node status, held, from the runner (program_runtime.node_statuses) through its validator, the Composer parser and the node/row styles. The frontend cannot infer it: a held leaf and a later, not-yet-started sibling both look idle under a running parent.
  • Colour: C, E and F reuse the running colour, since the node is part of the running execution, and change only the line or add a badge. G, H and I add a sixth status colour: magenta is used by no other status; orange sits between running yellow and failure red, so it needs a second look to tell apart at a glance.
  • Motion: only C animates; it stops under the system's "reduce motion" setting. Running nodes do not animate today, so the waiting nodes would be the only moving thing on the canvas, which is where the operator should look next.
  • Collapsed rows: the same treatment applies to the row's border and bar; the badge variants put the pause mark at the end of the row.
