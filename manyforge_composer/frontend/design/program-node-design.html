Program node colors and content

Approved 2026-09-26: the page opens on the approved design: Five families palette, Icon only treatment, category icon in a side band (31 px icon, 44 px bands), simplified content, word breaks with 2 lines, status border as today, status symbol offset 2 px, name margin 0, node width 200 px. The controls stay for future comparison; the app itself uses these values fixed.

Every node uses the exact node styling from the Composer stylesheet, including the status borders and the selection outline. Only the category treatment and the node content change. Nothing is applied to the app until you approve it.

The catalog has eleven categories. Today only four (motion, logic, control flow, scene) have their own color; the other seven use the default blue-grey. The "Dull cool" palette colors all eleven; the reference palettes show "none" for the categories they leave uncolored.

Category icons

One line icon per category. Every icon is a square of the same size; each drawing is scaled and centered so its longer side fills the same area, with transparent space around it. Drawn on a 16 px grid in the category's color (grey where a palette leaves the category uncolored). Shown here at 40 px; inside nodes they follow the icon size slider (default 31 px). The recovery icon is a circular arrow, deliberately not a stop sign.

Control-flow node icons (approved 2026-09-27)

One icon per control-flow node instead of the shared control-flow icon, in the same line style and family color. Sequence (→) and Parallel (⇉) use the standard behavior-tree symbols from Colledanchise and Ögren, also used by BehaviorTree.CPP/Groot; Fallback keeps a drawn fork instead of the standard ? (the first path fails, the next is taken). Decorators have no standard per-node symbol (the notation only draws a diamond), so Inverter, Repeat, Retry and Timer use common pictograms. A cross means failure (Fallback, Retry). The repeat loop is rectangular so it never reads as the circular recovery arrow. Every drawing is fitted with the same rule as the category icons: its longer side fills 12 of 16 units, centered.

Operation control node icons (approved 2026-09-27)

One icon per node of the Operation control category (catalog id recovery), in the execution-control color. Stop is a circle with the familiar stop symbol inside; Full Stop uses an octagon because it stops the whole cell, not one operation. Reset is a counter-clockwise arrow around a start point, and Apply offered recovery is a lifebuoy: taking the recovery the owner offers.

Simulation icon alternatives (A6 approved 2026-09-27)

Today's simulation icon (a play button in a frame) reads as a video player. Option A (a ball thrown over a ground plane) was preferred; A2–A5 are variations on it. Orbit, digital twin and monitor alternatives were reviewed and not chosen.

Notes on the simplified content

  • Symbols exist only per kind, not per category. In the app the canvas uses • for a leaf while the node palette uses ⬤ (and ▦ for templates); the proposal uses one drawn set for both.
  • The corner symbol shows the node kind: filled diamond = composite (many children), outlined diamond = decorator (one child), circle = leaf. The exit handle still shows whether children are allowed.
  • The symbol takes the availability color that the dot has today. The three symbols are drawn in the same box, so they look the same size.
  • "Configuration required" is amber (#d5a34b) and "unavailable" is grey (#7d8d96), the app's availability colors. Compare the Add scene object and Command gripper position nodes below. The tooltip keeps the text, so the meaning never relies on color alone.
  • The catalog id (for example motion.move_to_pose) stays visible in the inspector when the node is selected.
