Changes, Apply and status: proposal

Today the badges at the top left belong to the open workspace (Program and Scene show the Program, Deployment shows the Deployment), so changes elsewhere are invisible; the Deployment button's colour and dot show runtime health, not changes; and Execute is allowed with unapplied changes. Proposed: an amber marker on the workspace whose Draft is not applied, explaining tooltips, Execute blocked until Apply or Discard, and a legend.

1 · Where changes are

Two alternatives. Both show Program and Deployment state in every workspace; Scene edits count as Program changes (the Scene is part of the Program document). Tooltips as in section 2 go on the badges (and, for A, on the button).

A · Amber fill when anything is pending

The Program or Deployment button fills amber when at least one of its Draft / Saved / Applied badges is amber; otherwise it keeps the default look. Deployment keeps its border colour and dot for runtime health. The badges at the top left stay as today.

3 · Execute blocked until Apply or Discard

No new mechanism: Execute already requires the Program Draft to be the applied Program (Scene edits included). The same check adds the Deployment Draft. Execute's tooltip names which document is pending. During a run, authoring is locked, so nothing new can become pending mid-run; Stop, Halt and Reset are never blocked.
